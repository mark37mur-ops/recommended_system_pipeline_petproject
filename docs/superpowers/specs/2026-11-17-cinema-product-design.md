# Кино на вечер: продуктовый интерфейс и постеры

Дата: 2026-11-17. Статус: проект дизайна для финального подтверждения.

## Согласовано пользователем

- Тёмная стилистика кинотеатра с красным акцентом и механикой карточек/свайпов.
- Первые минимум пять разных фильмов оцениваются звёздами 1–5.
- После знакомства пользователь получает рекомендации с настоящими постерами.
- Дальше: «Хочу посмотреть», «Не интересно», «Пропустить» и возможность оценить просмотренное.
- На пользовательских экранах отсутствуют названия алгоритмов, модели, версии, кэш,
  NDCG, названия датасетов и инфраструктуры. Объясняющие ошибки — обычным языком.

## Подходы

1. Тёмный кинотеатр, крупные постеры и красный акцент: выбран пользователем.
2. Полностью игровой Tinder-интерфейс: использовать механику, не визуальный стиль.
3. Светлый киножурнал с сеткой: отклонён в пользу кинотеатра.

Сохранить FastAPI/Jinja2 и простой JavaScript: React не нужен для трёх экранов.

## Экран 1: знакомство

Заголовок «Найдём кино на вечер». Подпись «Оцените хотя бы 5 фильмов, которые смотрели».
Сетка узнаваемых фильмов разных жанров: постер 2:3, название, год, пять звёзд,
действие «Не смотрел». Прогресс «3 из 5»; кнопка «Подобрать кино» активна с пяти оценок.
Можно оценить больше пяти. Поиск помогает найти знакомый фильм вне первой подборки.
Пропуск заменяет карточку, не создаёт оценку и не увеличивает прогресс.
Засчитываются только успешно сохранённые оценки разных movie_id.
Повторная оценка одного фильма не увеличивает счётчик.

Возврат: прочитать историю с сервера. С пятью оценками сразу открывать подборку;
с меньшим числом — восстановить звёзды и прогресс. Cookie и существующие оценки сохранить.

## Экран 2: подборка

Одна активная карточка: большой постер, название, год, жанры. Ниже большие кнопки
«Не интересно», «Пропустить», «Хочу посмотреть»; вторичное действие «Уже смотрел»
раскрывает звёзды. Свайп влево = не интересно, вправо = хочу посмотреть.
Обычный вертикальный скролл телефона не должен случайно засчитываться как свайп.
Кнопки и клавиатура обеспечивают те же действия; анимации учитывают reduced-motion.

Успешная запись переводит к следующей карточке. Во время записи повторное нажатие
блокируется; при сбое карточка остаётся, ошибка понятна, доступен повтор.
Звёздная оценка немедленно пересчитывает рекомендации по существующему fold-in.
Сохранение и отказ исключают фильм из очереди и добирают карточки из выдачи.
Пропуск не означает «плохой фильм», скрывает карточку только в текущей сессии.
Все исчерпанные карточки: понятный экран «На сегодня всё», поиск и возврат к оценкам;
не возвращать отвергнутые фильмы ради заполнения десяти мест.

## Навигация

«Подборка» / «Хочу посмотреть» / «Мои оценки». На телефоне нижняя панель,
на широком экране компактное верхнее меню. Название сервиса: «Кино на вечер» (решение автора).
«Хочу посмотреть»: сетка сохранённых фильмов с удалением и «Уже смотрел».
«Мои оценки»: постеры и изменяемые звёзды; поиск доступен и после первого входа.
Пункт «О сервисе» — небольшой диалог в подвале с обязательными источниками изображений,
без технического описания моделей. Не делать отдельное меню «О проекте» на главном экране.

## Семантика сигналов

Звёзды — оценка просмотренного фильма; только они пишутся в ratings и поступают в
существующее обучение. «Хочу посмотреть» не преобразуется в 5, «Не интересно» не
преобразуется в 1: намерение и впечатление различаются.

Новая movie_feedback: user_id, movie_id, state (watchlist/dismissed), updated_at;
уникальность (user_id,movie_id), внешние ключи. Изменение состояния — upsert.
Оба состояния исключаются из колоды. Удаление из watchlist возвращает фильм в пул,
если он не оценён; оценка удаляет прежнее намерение и исключает фильм по ratings.
Отрицательный сигнал этой версии действует как исключение конкретного фильма,
без необоснованной смены жанрового профиля. Персональный вкус обучается по звёздам.

Работать с существующей подписанной cookie; пользователь определяется только сервером,
никогда user_id из тела запроса. Сохранять лимиты, квоты, защиту MovieLens-id.
Feedback и ratings атомарно согласованы; после изменений инвалидировать кэш.
Фильтровать исключения и на cache-hit, и на свежей выдаче, и в fallback.
Импрессии записывать для фактически возвращённых пользователю фильмов.

## Постеры и русские названия

Источник, предложенный автором: TMDB, бесплатный developer API для некоммерческого демо.
Нужен API Read Access Token владельца; он не обнаружен в текущей конфигурации.
Секрет вводится отдельно на D: вне git; в браузер и публичные файлы не попадает.
Официальные условия: https://developer.themoviedb.org/docs/faq
Изображения: https://developer.themoviedb.org/docs/image-basics

Обогащение каталога отдельной командой: искать по нормализованному названию и году,
проверять соответствие; не связывать произвольно первый результат. Для уверенного
совпадения сохранять tmdb_id, poster_path, русское название (если есть), источник.
Новые поля — отдельная movie_metadata с movie_id primary key: не менять существующие
таблицы и не переписывать исходные названия, на которых училась модель.
CLI повторяемый, с таймаутом, backoff и ограничением числа запросов. Сначала наиболее
популярные фильмы и onboarding; затем весь каталог. По запросу к API внешнего поиска нет.
Строго HTTPS и доверенный image.tmdb.org; если требуется прокси — только по movie_id,
без произвольных URL, с таймаутом и ограничением размера, а не открытый прокси.
Проверить доступность картинок с VPS и клиентского браузера перед публикацией.

Постер не найден/не загрузился: аккуратная локальная заглушка 2:3 с названием и годом,
без сломанной иконки. Заглушки не считаются выполнением задачи реальных постеров.
В «О сервисе» официальный логотип TMDB и обязательное уведомление:
“This product uses the TMDB API but is not endorsed or certified by TMDB.”

Каталог остаётся MovieLens 1M: не обещать современные релизы и не расширять каталог
из TMDB автоматически. Новые фильмы означают новые для пользователя.

## Проверка и выпуск

- Unit: звёзды и intent раздельны; upsert, пропуски, исключения на всех путях кэша;
  сопоставление постеров не выбирает неправильный год/название.
- Integration Postgres/Redis: существующая cookie, история после перезагрузки,
  сохранение/удаление, отрицательный сигнал, ошибки записи без потери действий.
- Browser desktop + mobile: первый вход, 5 оценок, карта, кнопки/свайпы, история,
  обновление страницы, пустые состояния, загрузка/отказ изображения, ошибки сети.
- Проверить отображаемый текст: нет ALS, LightGBM, NDCG, model version, cache, MovieLens.
  Служебные API/метрики/дашборды и внутренние параметры остаются для администрирования.
- Review logic + quality параллельно, затем CI и существующий деплой с откатом.
  Bootstrap create_all должен создать новые таблицы до запуска обновлённого API.
- Реальные постеры на onboarding и персональной выдаче — отдельная приёмка;
  до токена допускается только локальная разработка, не объявлять публичную версию готовой.

## За рамками

Регистрация, аккаунты между устройствами, современные фильмы, новый алгоритм рекомендаций,
оплата, социальные функции. Не очищать пользовательские оценки или рабочие тома.
